# Условие: кандидатогенерация для поиска услуг Авито

Источник: текст задания, предоставленный пользователем. Оформление таблиц и примеров приведено к Markdown; требования и численные параметры сохранены.

## О задаче

Пользователи Авито ищут услуги короткими запросами: «автоподбор», «скупка телевизоров», «баня на дровах», «монтаж видеодомофонов», «обзвон по базе».

По каждому запросу в корпусе находятся тысячи объявлений исполнителей. Поиск устроен каскадом: сначала этап кандидатогенерации быстро отбирает из всего корпуса небольшое множество подходящих объявлений, затем модели ранжирования упорядочивают только их.

Главное требование к кандидатогенерации — полнота. Если нужное объявление не попало в кандидаты, ранжирование его уже не вернёт.

## Цель

Разработать решение, которое для каждого поискового запроса отбирает из корпуса до 50 объявлений — кандидатов для ранжирования. Решение:

1. Получает текст поискового запроса и остальные признаки.
2. Находит подходящие объявления услуг в корпусе.
3. Возвращает до 50 `item_id`.

Подходящие объявления — те, которые пользователь в итоге выбрал по этому запросу. Обычно это одно-два объявления, иногда больше. Качество определяется долей подходящих объявлений, попавших в 50 кандидатов.

## Входные данные

Три файла Parquet:

- `train.parquet` — 497 673 строки. Каждая строка — положительная пара «запрос — выбранное объявление», с признаками `search_*` и `item_*`.
- `benchmark_queries.parquet` — 2 452 запроса без разметки. Содержит `query_id` и признаки запроса в том же формате, что в обучающей выборке.
- `benchmark_items.parquet` — корпус из 189 212 объявлений. Содержит `item_id` и признаки объявления в том же формате, что в обучающей выборке.

Все подходящие объявления для запросов бенчмарка есть в этом корпусе.

Пример обучающей пары:

```text
search_query: "автоподбор"
search_infm_params_text: "Рейтинг пользователя 4 звезды и выше"
item_title_raw: "Автоподбор Разовый осмотр автомобиля"
```

Это означает, что пользователь искал «автоподбор» с фильтром по рейтингу и выбрал указанное объявление.

Ссылка на исходные данные: https://disk.yandex.ru/d/sNhfo0YOjGtufg

## Ожидаемый результат

Файл `answer.csv`, разделитель — запятая, кодировка — UTF-8, ровно две колонки:

| Колонка | Тип | Описание |
| --- | --- | --- |
| `query_id` | Строка | Идентификатор запроса из `benchmark_queries.parquet`, ровно 16 символов, регистр важен |
| `answer` | Строка | До 50 `item_id`, разделённых пробелами |

`item_id` — строка ровно из 16 символов `0-9a-f`, например `1382564bf8994a83`, в точности как в `benchmark_items.parquet`.

Требования:

- Одна строка на каждый `query_id`, без пропусков, лишних строк и повторов; порядок произвольный.
- Не больше 50 `item_id` в строке, без повторов внутри строки.
- Каждый `item_id` существует в корпусе.
- Возвращаются идентификаторы объявлений, а не заголовки или номера строк.
- Других колонок, включая индекс, быть не должно.

Иллюстрация формата (многоточие обозначает продолжение списка и не должно попадать в настоящий файл):

```csv
query_id,answer
00WuFMaXSFZBxSzT,1382564bf8994a83 121fa7f5e765ce00 f3801ec4fa472597 ...
03ztb1gtRFC4K4vP,b0dd913d84ca1f61 e36f6c3245e05ab6 a3c3aa4703977bfe ...
```

### Сохранение в Python

`query_ids` — идентификаторы запросов; `predictions` — списки до 50 `item_id` для каждого запроса.

```python
answer = pd.DataFrame({
    'query_id': query_ids,
    'answer': [' '.join(top50) for top50 in predictions],
})
answer.to_csv('answer.csv', index=False)
```

## Целевая метрика

Recall@50 — доля подходящих объявлений, попавших в топ-50, усреднённая по запросам:

```text
Recall@50 = mean_по_запросам(|топ-50 ∩ релевантные| / |релевантные|)
```

Пример:

| Запрос | Подходящих объявлений | Попало в 50 | Вклад |
| --- | ---: | ---: | ---: |
| А | 1 | 1 | 1,0 |
| Б | 2 | 1 | 0,5 |
| В | 1 | 0 | 0,0 |

Итог: `(1,0 + 0,5 + 0,0) / 3 = 0,5`.

Порядок объявлений внутри ответа на метрику не влияет. Доступно 7 попыток; засчитывается лучший результат.

## Ограничения и условия

- Запрещены хардкод ответов под конкретные `query_id` и попытки вручную восстановить тестовую разметку.
- Запрещены плагиат и копирование решений других кандидатов.
- Использование open-source моделей, библиотек и готовых подходов необходимо указать в описании решения.
- Решение должно воспроизводиться у проверяющего локально, без обращений к внешним API.
- Очень важно сопровождать решение комментариями; голый код без пояснений не приветствуется.

Допускаются классические ML-модели, нейросетевые модели, методы информационного поиска, правила, эвристики, гибридные подходы, open-source модели и библиотеки, если они разворачиваются локально и не обращаются к внешнему API.

### Перед отправкой

Проверить названия колонок, отсутствие лишних или недостающих `query_id`, повторов внутри ответа и строк с числом объявлений больше 50. Ошибки формата приводят к ошибке проверки.

Отдельно проверить `item_id`: другой регистр, лишние символы или слитная строка могут не вызвать ошибку проверки, но такие объявления не засчитаются и займут место в ответе.

Частые ошибки:

- Идентификаторы преобразованы в числа, потеряли ведущие нули или перешли в экспоненциальную запись. Работать с ними как со строками; не открывать CSV в Excel для пересохранения.
- Файл сохранён с индексом: необходимо `index=False`.
- Идентификаторы записаны через запятую или как Python-список; нужен один пробел между ними.
- `item_id` приведены к верхнему регистру; нужны строчные буквы, как в корпусе.
